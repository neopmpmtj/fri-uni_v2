## Findings

Severity: **High** = wrong money / lock, HTTP 500 on a normal staff/admin action, or CLI behaviour that will bite the later agent. **Medium** = incorrect quote or workflow without a crash. **Low** = polish, missing logs, test gaps.

### High

**H1. Catalog admin: missing price-change reason is a 500, not a form error**  
`proformas/admin.py` `EquipmentModelAdmin.save_model` (same pattern on `TubingLengthAdmin`). The extra `reason` field is `required=False`. Changing `list_price` / `price` with an empty reason calls the service, which raises `ValidationError`. The admin catches it, `form.add_error`, then **re-raises**. Django admin does not turn that into a 200 form redisplay. Reproduced: POST to `/admin/proformas/equipmentmodel/<id>/change/` → `Internal Server Error`. The service test covers the helper, not this HTTP path.

**H2. Catalog admin: a price change discards other field edits**  
Same `save_model`: if price changed, it updates price on the **original** row and `return`s without `super().save_model`. Style, kind, BTU, or tubing length edited in the same save are dropped. Reproduced: indoor + new price → price saved, kind left indoor.

**H3. Staff line save with quantity &lt; 1 is an uncaught 500**  
`ProformaLine.quantity` is a plain `IntegerField` (no `MinValueValidator`). The form accepts `0` / negative. `add_line` / `_line_money` then raise `ValidationError`. `proforma_detail` does not catch it. Reproduced with the Django test client (exception bubbles; production `DEBUG=False` → 500). Same class of bug for any other uncaught service `ValidationError` on that view.

**H4. CLI `create_proforma` is not atomic — the agent path**  
`proformas/management/commands/create_proforma.py` calls `create_draft` then `add_line` per `--line` with **no `transaction.atomic`**. If a later line fails (unknown model id, bad qty), a live draft remains with the earlier lines. Reproduced: `--line <good>:1 --line 99999:1` → `CommandError` **and** `Proforma` count +1, status draft, one line. A retrying LLM agent will create another number (`PF-YYYY-0002`, …) rather than resume. There is also no `transaction` anywhere in the Python tree (numbering `IntegrityError` on concurrent create would 500 the web path too).

**H5. CLI invalid `--line` tokens raise `ValueError`, not `CommandError`**  
`int(parts[0])` / `int(parts[1])` are uncaught. Reproduced: `--line not-an-id:1` → `ValueError`. Fine for a human in a traceback; noisy and non-contract for an agent.

### Medium

**M1. Discount percent is unbounded**  
No 0–100 (or ≥ 0) check on `ProformaHeaderForm`, `create_draft`, or CLI `--discount-percent`. Reproduced: 150% on a €500 line → `discount_amount=750`, `grand_total=-250`. Negative extra labour is similarly allowed.

**M2. Empty drafts can be issued**  
`issue_proforma` does not require lines. Reproduced: status `issued`, `grand_total=0.00`, zero lines. Staff UI Issue is enabled with an empty grid.

**M3. Soft-delete client or site does not retire children**  
`delete_client` only sets `deleted_at` on the client. Live `Site` rows remain. Site list still shows them (`House 1` still in HTML). `create_draft` + `issue_proforma` still succeed and snapshot the deleted client’s name. `delete_site` is the same pattern: live proformas keep a FK to a hidden site and stay on the proforma list. Django FK traversal uses `_base_manager`, so this is **not** a 500 — it is an orphan workflow hole. There is no cascade or “in use” guard.

**M4. Issue ignores unsaved header fields**  
`templates/proformas/proforma_detail.html`: Issue/Cancel buttons `form="issue-form"`, a separate empty POST. Changing discount / labour / observations and clicking Issue without Save locks the **previous** DB values. Easy to issue the wrong totals.

**M5. Issued staff screens still read live FKs for display**  
Quote/PDF correctly use snapshots. The work page header (`proforma_detail.html`) prints `proforma.site.client.name` and `proforma.site.alias_1`; the list site column (`proforma_list.html`) does the same. After a client/site rename, staff list/detail disagree with the issued quote. Line catalog names on the issued work table use snapshots, but extra tubing still uses live `{{ line.tubing_length }}` (`TubingLength.__str__`), not `tubing_length_value`.

**M6. Issued quote omits snapshotted site fields**  
`issue_proforma` copies `site_alias_3`, `site_alias_4`, `site_notes`. `templates/proformas/includes/quote_body.html` only prints alias 1–2, street, postal code, city. PDF uses the same include.

**M7. Catalog admin hard-deletes**  
`Brand`, `Style`, `EquipmentModel`, `TubingLength`, `Parameter` use default admin delete (SQL DELETE), not `soft_delete`. Unused rows vanish; audit columns are bypassed. `PROTECT` on in-use FKs limits damage. Log admins correctly forbid add/change/delete.

**M8. Admin model forms use `fields = "__all__"`**  
Price forms expose always-on audit columns (`deleted_at`, `created_by`, …) on the change page. Easy to confuse with the intended catalog fields.

### Low

**L1.** `conf/urls.py` duplicates the `DEBUG` media `static()` block twice.  
**L2.** `templates/proformas/quote_pdf.html` hardcodes `<html lang="en">` even when `fu-lang=pt`.  
**L3.** Quote line kind: any value other than `"indoor"` is labelled outdoor (`quote_body.html`). After a correct issue this is fine; a blank kind would mislabel.  
**L4.** Data-points list `create proforma via agent/CLI` as a typical `activity_logs` action. CLI create does not call `log_activity` (issue and PDF download do).  
**L5.** CLI `--user` does not check `is_active`.  
**L6.** `next_proforma_number` orders by string `number` and formats four digits. Past 9999 in a year, lexicographic `max` is wrong (`PF-YYYY-10000` sorts before `PF-YYYY-9999`). Unlikely for this company; still a numbering bug.  
**L7.** Tests warn `No directory at: /workspace/staticfiles/` (Whitenoise). Harmless locally; `collectstatic` is not run in pytest.  
**L8.** Phase 7 PT check is HTML-only; PDF bytes are only checked for content-type and length.  
**L9.** Manager site-delete 403 is implemented like client delete but only client delete is tested.  
**L10.** POST actions on the wrong status (e.g. Issue on an already issued row) are silently ignored (page re-renders, no message).

## Suggested tests (not implemented here)

If/when these are fixed, the cheap tests that would have caught them:

- Admin POST price change without reason → 200 + form error, price unchanged.
- Admin POST price + kind together → both persist.
- Line POST `quantity=0` → 200 + form error, not 500.
- `create_proforma` with a bad second `--line` → exit non-zero **and** zero new proformas.
- `create_proforma --line not-an-id:1` → `CommandError`.
- Discount 150% / quantity 0 rejected at form or service.
- `issue_proforma` with no lines rejected (if that becomes the rule).
- Soft-delete client either hides sites or is refused while live sites exist.
- Quote HTML after renaming a brand still shows `brand_name` snapshot.
- Issued work page / list still show snapshot names after a live client rename.
