## Findings

Severity: **High** = wrong money / lock, HTTP 500 on a normal staff action, or CLI behaviour that will bite an agent. **Medium** = incorrect quote or workflow without a crash. **Low** = polish, missing display, test gaps, operational notes.

### Medium

**M1. HQ site client reassignment is an uncaught 500**

`SiteForm` exposes `client` for all sites, including headquarters. Saving an HQ site with `client` changed to another client that already has a live HQ violates `uniq_live_site_hq_per_client` (`proformas/models.py`). `site_list` saves via `_save_audited` with no `IntegrityError` handling.

Reproduced (temporary pytest, then removed): POST edit HQ site, set `client` to a client that already has HQ → `IntegrityError: UNIQUE constraint failed: proformas_site.client_id` → HTTP 500.

Staff are unlikely to do this often, but the site drawer allows it and the new HQ constraint makes it a real crash path.

### Low

**L1. `client_kind` and `client_country_code` snapshotted but not on quote**

`issue_proforma` writes both fields; [`quote_body.html`](../../templates/proformas/includes/quote_body.html) prints name, NIF, street, postal/city, phone, email only. Data-points lists kind and country as snapshot fields. Not wrong for money, but PDF/quote omit data that is frozen at issue.

**L2. Brand rename → issued quote HTML still untested**

`test_issue_snapshots_catalog_names` (phase6) checks at issue time. No HTTP test that renames `Brand` after issue and asserts quote HTML still shows `line.brand_name`. Prior review gap; still open.

**L3. HQ delete guard untested in main suite**

`delete_site` raises “Cannot delete the headquarters site” — reproduced manually during review. No pytest in the committed suite (only ad-hoc repro).

**L4. Client delete cascade (sites, no proformas) lightly tested**

Service cascades soft-delete to all sites. `test_admin_can_delete_client` only covers a client with HQ alone. Cascade with HQ + obra sites is not asserted.

**L5. Squashed `0001_initial.py` — dev DB must be reset**

Editing the initial migration (no new `0002`) means an existing `db.sqlite3` from the pre-billing schema fails (`OperationalError: table proformas_client has no column named kind`). Fix: delete `db.sqlite3`, `migrate`, `seed_demo`. Not a pytest issue (test DB is recreated); operators must know.

**L6. `seed_demo` does not backfill HQ for pre-existing clients**

`_seed_clients_and_sites` creates HQ only when `created` is true. Re-running seed on an old DB after migrate-but-not-reseed leaves clients without HQ. Fresh migrate + seed is fine.
